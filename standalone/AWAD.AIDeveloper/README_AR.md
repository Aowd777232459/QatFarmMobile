# AWAD AI Developer 1.0

تطبيق مستقل من عواد سوفت لتحويل الدردشة إلى دورة تطوير برمجية فعلية وآمنة على جهاز المستخدم.

## ماذا يفعل الإصدار الأول؟

- فتح أي مشروع محلي على الكمبيوتر وتحليل بنية الملفات.
- محادثة عربية مع نموذج ذكاء اصطناعي عبر OpenAI Responses API.
- إنشاء خطة تعديلات بصيغة قابلة للتدقيق قبل لمس الملفات.
- كتابة ملفات جديدة، استبدال نصوص محددة، حذف ملفات، وتشغيل أوامر Build/Test مسموحة.
- إنشاء نقطة استعادة ZIP تلقائياً قبل كل عملية تطبيق.
- وضع **التطوير التلقائي**: يطبق الخطة، يشغل البناء/الاختبار، ثم يعيد إرسال الأخطاء للنموذج لدورة إصلاح جديدة حتى 5 دورات.
- ذاكرة محلية لكل مشروع تحفظ ملخص المهام والنتائج السابقة.
- **نسخة تطوير آمنة Staging**: ينسخ المشروع إلى مجلد منفصل ثم يعمل على النسخة بدلاً من الأصل.
- حماية من الكتابة خارج مجلد المشروع ومن تعديل `.git` أو ملفات الأسرار والمفاتيح.
- قائمة أوامر تطوير مسموحة بدل تنفيذ shell مفتوح.

## التطوير الذاتي الآمن

لا يعدّل البرنامج الملف التنفيذي الذي يعمل منه مباشرة. لتطوير AWAD AI Developer نفسه، افتح مجلد مصدره ثم اضغط **إنشاء نسخة تطوير آمنة**. بعدها اطلب من الدردشة تعديل النسخة المرحلية، بنائها واختبارها. بعد نجاحها يمكن اعتماد الإصدار الجديد يدوياً.

## التشغيل من المصدر

يتطلب .NET 10 SDK:

```powershell
cd AWAD.AIDeveloper
dotnet run
```

يفتح التطبيق محلياً على:

`http://127.0.0.1:45873`

## مفتاح الذكاء الاصطناعي

الأفضل تعريفه كمتغير بيئة في Windows:

```powershell
setx OPENAI_API_KEY "YOUR_KEY"
```

ثم أعد فتح التطبيق. ويمكن إدخاله في شاشة الإعدادات للجلسة الحالية فقط. التطبيق لا يكتب المفتاح داخل المشروع.

النموذج الافتراضي هو `gpt-5.6-sol` ويمكن تغييره من الإعدادات.

## حدود الأمان في 1.0

الأوامر التلقائية تبدأ فقط بواحد من الأدوات التالية:

`dotnet, npm, npx, node, git, python, python3, py, pytest, cargo, go, mvn, mvnw, gradle, gradlew, java`

لا يسمح بمسارات مطلقة للكتابة، ولا بالكتابة خارج مجلد المشروع، ولا بتعديل ملفات المفاتيح أو الأسرار، ولا بالأوامر الإدارية أو النظامية الخطرة.

## الهيكل

1. واجهة دردشة عربية.
2. Project Context Builder لاختيار الملفات الأقرب للمهمة.
3. Planner Agent لتحويل الطلب إلى JSON Plan.
4. Safety Gate للتحقق من المسارات والأوامر.
5. Checkpoint Engine لنسخة ZIP قبل التنفيذ.
6. Executor لتطبيق التغييرات داخل Workspace فقط.
7. Verifier لتشغيل Build/Test.
8. Repair Loop لإعادة أخطاء البناء للنموذج.
9. Project Memory لحفظ نتائج المهام السابقة.

## المرحلة التالية

- Git branch/commit تلقائي قبل كل مهمة.
- Diff مرئي قبل/بعد لكل ملف.
- دعم أكثر من مزود ذكاء اصطناعي.
- Function Calling بدل بروتوكول JSON النصي.
- SQLite للذاكرة وسجل الإصدارات.
- Terminal حي ومحرر ملفات داخلي.
- Agent منفصل للمراجعة واختبارات الجودة.
- Update Installer للتطوير الذاتي بعد موافقة المدير.
